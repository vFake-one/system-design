# Final Project Report Structure

Suggested chapter outline for the academic report. Word counts are indicative for a Year 2 semester project (~8,000–12,000 words plus appendices).

1. **Title page** — project title, student name, number, programme, date.
2. **Declaration** — own work; prototype not for clinical use.
3. **Abstract** (~200 words) — problem, method, Flask/SQLite prototype, rule-based ranking, results of tests, limitations.
4. **Acknowledgements**
5. **Table of contents, list of figures, list of tables, abbreviations**
6. **Chapter 1 Introduction** — background, problem, aim, objectives, significance, report structure. *(docs/01–03)*
7. **Chapter 2 Literature / existing approaches** — informal calls, panic buttons, telehealth; why a check-in log is different; responsible AI wording.
8. **Chapter 3 Requirements and feasibility** — actors, FR/NFR, feasibility, ethical constraints. *(docs/05–06)*
9. **Chapter 4 System design** — architecture, use cases, DFDs, ERD, UI, alert workflow. *(docs/07–12)*
10. **Chapter 5 Implementation** — stack, folder structure, security (hashing, CSRF, RBAC), scanner, screenshots.
11. **Chapter 6 AI component** — features, rules, why ML is experimental, evaluation honesty. *(docs/17)*
12. **Chapter 7 Testing** — test cases, results, discussion of defects. *(docs/16)*
13. **Chapter 8 Evaluation** — objectives met/not met; usability observations; what the demo does not prove.
14. **Chapter 9 Conclusion and future work** *(docs/20)*
15. **References**
16. **Appendices**
    - A User manual *(docs/18)*
    - B Installation *(docs/14)*
    - C Full schema SQL
    - D Sample (synthetic) data description
    - E Test output
    - F Ethics / disclaimer text
    - G Source code listing or repository link

**Figures to include:** architecture, use-case, DFD 0 and 1, ERD, alert flowchart, 4–6 screenshots (login, elderly check-in, caregiver dashboard, alert explanation).
